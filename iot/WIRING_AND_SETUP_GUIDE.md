**Barangay Tagpopongan Water Management System (IGACOS)**

## 📋 Physical Sensor Checklist (Exact Physical Scope)

The central reservoir monitoring unit uses an **ESP32 DevKit V1** and exactly **three physical sensors**:

1. **ESP32 DevKit V1** (30-pin or 38-pin version, dual-core Tensilica Xtensa 32-bit LX6).
2. **JSN-SR04T Waterproof Ultrasonic Distance Sensor** (with waterproof transducer and transceiver driver board).
3. **Gravity Analog Turbidity Sensor** (optical infrared probe + signal adapter module with A/D switch).
4. **Gravity Analog TDS Meter Sensor** (waterproof titanium probe + signal conditioning adapter module).
5. **Voltage Divider Resistors**: **1kΩ** and **2kΩ** resistors (to protect ESP32 GPIO 19 from 5V ECHO pulse).
6. **5V Power Supply / Regulated Power Adapter** (minimum 5V / 1.5A to prevent WiFi transmission brownouts).
7. **Jumper Wires** (Female-to-Male and Male-to-Male).

> [!IMPORTANT]
> **NO OTHER SENSORS ARE PHYSICALLY INSTALLED.**
> The system has **NO pH sensor**, **NO pipe flow sensor (YF-S201)**, and **NO physical temperature sensor**.
> Household consumption is tracked through regular manual meter readings, and central reservoir telemetry only ingests and reports Water Level, Turbidity, and TDS.

## 🛡️ Critical Hardware Rules & Electrical Protections

### 1. Dedicated ADC1 Pins (GPIO 34 & GPIO 35)
- The ESP32 features two 12-bit ADC peripherals: **ADC1** and **ADC2**.
- **ADC2** (GPIO 0, 2, 4, 12–15, 25–27) is **internally disabled by the ESP32 Wi-Fi hardware stack** whenever the Wi-Fi radio is active.
- Attempting to read analog sensors on ADC2 pins during Wi-Fi transmission returns corrupted or 0 values.
- Therefore, both analog sensors **MUST** be connected to **ADC1 pins**:
  - `GPIO 34` = ADC1_CH6 (Turbidity)
  - `GPIO 35` = ADC1_CH7 (TDS)
- GPIO 34 and GPIO 35 are dedicated input-only pins with no internal pull-up/pull-down resistors, making them ideal for analog signal acquisition.

### 2. JSN-SR04T 5V Echo Voltage Divider
- The JSN-SR04T transceiver module is powered from 5V and outputs a 5V logic signal on its `ECHO` pin.
- Connecting 5V directly to ESP32 GPIO pins will damage or degrade the ESP32 input pin (rated for 3.3V max).
- Construct a simple 1kΩ / 2kΩ resistive voltage divider between `ECHO` and `GPIO 19`:
  ```
  JSN-SR04T ECHO (5V) ------> [ 1kΩ Resistor ] ----+----> ESP32 GPIO 19 (3.3V logic)
                                                    |
                                             [ 2kΩ Resistor ]
                                                    |
                                                   GND
  ```
  $$\text{V}_{\text{GPIO19}} = 5.0\text{V} \times \frac{2\text{k}\Omega}{1\text{k}\Omega + 2\text{k}\Omega} = 3.33\text{V}$$

### 3. Turbidity Module "A / D" Mode Switch
- The Gravity analog turbidity module has a small slide switch labeled **"A / D"** (Analog / Digital).
- **Ensure the switch is set to "A" (Analog)**.
- If left on "D", the module only outputs a binary ON/OFF signal governed by the onboard trim potentiometer, which will fail continuous turbidity measurement.

## 📐 Reservoir Calibration & Physics

### A. JSN-SR04T Water Level Calibration
The firmware calculates the water volume percentage based on distance measured from the sensor transducer:
```cpp
// Distance from sensor face to the bottom of the empty tank (in cm)
const float TANK_TOTAL_DEPTH_CM = 200.0;

// Minimum dead-band / blind-zone distance from sensor face to max capacity line (in cm)
const float SENSOR_OFFSET_CM    = 20.0;

// Effective measurable water column height
const float MAX_WATER_HEIGHT_CM = TANK_TOTAL_DEPTH_CM - SENSOR_OFFSET_CM;
```

1. **Sensor Placement**:
   - Mount the waterproof transducer pointing perpendicularly downwards toward the center of the water surface.
   - Maintain at least **20 cm clearance** above the highest water level mark. Ultrasonic transducers cannot measure objects closer than their minimum physical blind zone (~20 cm).
2. **Measurement Calibration Steps**:
   - Measure the exact distance from the sensor face to the bottom of the empty reservoir. Set this value to `TANK_TOTAL_DEPTH_CM`.
   - Measure the distance from the sensor face to the top overflow / maximum filling mark. Set this value to `SENSOR_OFFSET_CM`.
3. **Sensor Disconnection & Timeout Handling**:
   - If no echo pulse returns within 30 milliseconds (e.g., sensor disconnected, cable cut, or distance out of range), the firmware logs:
     `[JSN-SR04T] ERROR: Echo timeout or sensor disconnected. Water level reading unavailable.`
   - In this case, `readWaterLevelPercentage()` returns `-1` and the HTTP JSON payload transmits:
     `"water_level_percentage": null`
   - **No fake fallback percentage (e.g. 68%) is ever transmitted.** The backend accepts `null` water level and dashboards clearly show `N/A` or `Awaiting data` without generating false alarms.

### B. Turbidity Sensor Calibration
1. **Operating Characteristic**:
   - Pure, clear water produces an analog voltage around **2.5V to 3.3V** (NTU < 5.0).
   - Increasing particulates and cloudiness scatters light, dropping the received photodiode voltage below **2.0V**.
2. **Zero-Point Potentiometer Tuning**:
   - Dip the probe in clear distilled or clean tap water.
   - Measure the voltage on `GPIO 34` with the serial monitor.
   - If the voltage is below 2.5V in clear water, adjust the small blue trim potentiometer on the turbidity adapter board until the voltage reads between 2.8V and 3.2V.
3. **Threshold Behavior**:
   - When turbidity exceeds **5.0 NTU**, the WaterHall backend automatically records an elevated turbidity event and dispatches community alerts.

### C. TDS Meter Sensor Calibration
1. **Operating Formula**:
   $$\text{TDS (ppm)} = \left(133.42 \times V^3 - 255.86 \times V^2 + 857.39 \times V\right) \times 0.5$$
2. **Temperature Assumption (25°C)**:
   - Water electrical conductivity varies by ~2% per °C. Because there is **no physical temperature probe** in the hardware deployment, the compensation coefficient is fixed to **1.0** (standard 25°C baseline reference).
3. **Probe Handling**:
   - Do NOT submerge the adapter electronics board; submerge only the waterproof electrode probe.
   - Keep the probe away from the tank walls and metallic pipe fittings to avoid stray capacitive readings.

## 🛠️ Step-by-Step Arduino IDE Setup

### Step 1: Install ESP32 Board Core
1. Open **Arduino IDE** (v1.8.x or v2.x).
2. Navigate to **File > Preferences**.
3. In **Additional Boards Manager URLs**, paste:
   ```
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
4. Navigate to **Tools > Board > Boards Manager...**, search for `esp32` by Espressif Systems, and install version 2.0.x or latest.

### Step 2: Configure Sketch Credentials (Choose Test or Production)
The canonical firmware (`iot/waterhall_esp32_reservoir/waterhall_esp32_reservoir.ino`) includes `#include "device_config.h"`. Before compiling, copy either the local test template or production template to the untracked `device_config.h`:

- **For Local Physical Bench Testing:**
  ```bash
  cp iot/waterhall_esp32_reservoir/device_config.local.example.h iot/waterhall_esp32_reservoir/device_config.h
  ```
  Fill in your 2.4 GHz Wi-Fi SSID/password, your development machine's LAN IP (`http://<LAN-IP>:8000`), and your local `IOT_DEVICE_SECRET` (at least 32 characters). Keep `ALLOW_INSECURE_LOCAL_HTTP = true`.

- **For Production Station Provisioning:**
  ```bash
  cp iot/waterhall_esp32_reservoir/device_config.production.example.h iot/waterhall_esp32_reservoir/device_config.h
  ```
  Fill in the station 2.4 GHz Wi-Fi credentials, production URL (`https://waterhall-samal.vercel.app`), a **NEW** random 32+ character secret matching the production Vercel/cloud backend, and the verified `ROOT_CA` PEM certificate. Keep `ALLOW_INSECURE_LOCAL_HTTP = false`.

> [!CAUTION]
> `device_config.h` is strictly ignored by Git in `.gitignore`. Never commit real Wi-Fi credentials, secrets, or certificates.

### Step 3: Flash to ESP32
1. Connect the ESP32 to your PC via a high-quality Micro-USB / USB-C data cable.
2. Select **Tools > Board > DOIT ESP32 DEVKIT V1** (or ESP32 Dev Module).
3. Select **Tools > Port > COMx** (the COM port assigned to the CP2102/CH340 USB-UART chip).
4. Click **Upload**. If the upload hangs on `Connecting........_____.....`, press and hold the board's **BOOT** button for 2 seconds.

## 🔍 Hardware Troubleshooting Matrix

| Symptom / Error | Probable Cause | Corrective Action |
| :--- | :--- | :--- |
| **`[JSN-SR04T] ERROR: Echo timeout`** | 1. Sensor echo wire loose.<br>2. Transducer distance < 20 cm (blind zone).<br>3. Voltage divider missing or miswired. | 1. Check connections on GPIO 18 (TRIG) and GPIO 19 (ECHO).<br>2. Ensure sensor has at least 20 cm clearance above water.<br>3. Verify 1kΩ / 2kΩ resistors and common GND. |
| **Water Level shows `N/A` on Dashboard** | Ultrasonic sensor is timed out or null; backend received `water_level_percentage: null`. | Expected fail-safe behavior. Check physical transducer wiring at the reservoir tank. |
| **Turbidity stuck at `0.5 NTU` or `>30 NTU`** | 1. Adapter switch set to "D".<br>2. Potentiometer out of alignment. | 1. Flip toggle switch on turbidity board to **"A" (Analog)**.<br>2. In clear water, turn trimmer potentiometer until ADC reads ~2.8V–3.2V. |
| **TDS reads `0 ppm` or erratic fluctuating values** | 1. Probe not submerged.<br>2. Probe touching metal tank wall.<br>3. Poor ground connection. | 1. Ensure both electrode pins are submerged in water.<br>2. Isolate probe from metal pipes and grounded pumps.<br>3. Check common ground between ESP32 and sensor. |
| **ESP32 reboots continuously during WiFi TX (`Brownout detector was triggered`)** | USB port or power supply cannot deliver peak current (>500mA) required during RF transmission. | Use an external 5V / 2A DC regulated power supply or powered USB hub. Add a 100µF capacitor across VIN and GND. |
| **`[HTTP] Server Response [401]`** | `IOT_DEVICE_SECRET` mismatch between firmware header and backend environment. | Verify that `IOT_DEVICE_SECRET` in `device_config.h` exactly matches `IOT_DEVICE_SECRET` on the server. |
| **`[HTTP] Server Response [503]`** | Server ingestion endpoint has no `IOT_DEVICE_SECRET` set in environment. | Ensure `IOT_DEVICE_SECRET` is configured in backend `.env` / runtime environment. |
| **`[WiFi] Connection failed`** | Network is 5 GHz only or signal too weak. | ESP32 hardware only supports 2.4 GHz 802.11 b/g/n networks. Connect to a dedicated 2.4 GHz SSID. |

## 📋 Section 6: Exact Local Physical Test Checklist (Bench Testing)

Follow this step-by-step verification checklist when bench-testing with the physical ESP32 and real sensors.
*Note: Do not claim calibration accuracy until sensors are physically calibrated with reference solutions and measured tank depths.*

- [ ] **A. Wiring Inspection**: Verify sensor connections against the Master Pin Connection Table:
  - JSN-SR04T `TRIG` to `GPIO 18`.
  - JSN-SR04T `ECHO` to `GPIO 19` through voltage divider.
  - Turbidity `AOUT` to `GPIO 34` (switch set to **"A"**).
  - TDS `AOUT` to `GPIO 35`.
  - Ensure **NO pH sensor**, **NO flow sensor**, and **NO temperature sensor** are wired.
- [ ] **B. Common Ground (GND)**: Verify all sensor GND pins share a solid, continuous electrical ground with the ESP32 GND rail.
- [ ] **C. JSN-SR04T ECHO Voltage Divider**: Confirm the 1kΩ / 2kΩ resistive divider drops the 5V echo pulse to ~3.3V on `GPIO 19` to protect the ESP32 input stage.
- [ ] **D. ESP32 Power-On**: Power the ESP32 via USB. Ensure the red power LED lights steadily and the blue status LED on `GPIO 2` begins blinking during initial Wi-Fi search.
- [ ] **E. Serial Monitor 115200**: Open Arduino IDE Serial Monitor at 115200 baud. Confirm boot banner:
  ```text
  WATERHALL IoT Reservoir Monitoring Station
  Barangay Tagpopongan, Island Garden City of Samal
  ```
- [ ] **F. Wi-Fi Connection (2.4 GHz)**: Confirm Serial Monitor shows connection dots and reports assigned IP:
  ```text
  [WiFi] Connected successfully!
  [WiFi] ESP32 Assigned IP: 192.168.1.xxx
  ```
  Status LED (`GPIO 2`) switches to steady ON.
- [ ] **G. Local Backend Connection**: Ensure the local Flask backend is running on `0.0.0.0:8000` on the PC and accessible from the ESP32's subnet.
- [ ] **H. Water Level Reading (JSN-SR04T)**: Point transducer at a flat surface (e.g., wall or water container at ~50 cm). Confirm Serial Monitor prints valid distance, calculated water height, and percentage between 0% and 100%.
- [ ] **I. Turbidity Reading**: Immerse probe in clean water. Confirm Serial Monitor prints:
  `[TURBIDITY] Raw ADC: ~3000-3600 | Voltage: ~2.5V-3.0V | NTU: < 5.0`
- [ ] **J. TDS Reading**: Immerse titanium pins in tap/well water. Confirm Serial Monitor prints:
  `[TDS] Raw ADC: ~1200-2200 | Voltage: ~1.0V-1.8V | TDS: ~80-250 ppm`
- [ ] **K. JSON Telemetry Assembly**: Confirm Serial Monitor logs the assembled payload:
  `{"water_level_percentage": <int>, "turbidity_ntu": <float>, "tds_ppm": <int>}`
  (strictly 3 sensor fields; no ph, flow, or temperature).
- [ ] **L. HTTP Response**: Confirm Serial Monitor receives HTTP 200:
  `[HTTP] Server Response [200]: {"message":"IoT sensor data ingested successfully","status":"success",...}`
- [ ] **M. Database Persistence**: Inspect local SQLite/PostgreSQL `reservoir_quality_readings` table. Confirm new row with matching `water_level_percentage`, `turbidity_ntu`, `tds_ppm`, and current UTC timestamp.
- [ ] **N. Admin Web Portal Display**: Open `http://localhost:8000/admin/`. Confirm the Central Reservoir telemetry card displays the exact water level %, turbidity NTU, and TDS ppm.
- [ ] **O. Resident Portal Display**: Open `http://localhost:8000/` or Flutter app. Confirm the Resident Dashboard shows matching reservoir telemetry without errors.
- [ ] **P. Ultrasonic Disconnect / Timeout Test**:
  1. Unplug JSN-SR04T `ECHO` jumper wire from `GPIO 19`.
  2. Confirm Serial Monitor prints: `[JSN-SR04T] ERROR: Echo timeout or sensor disconnected. Water level reading unavailable.`
  3. Confirm transmitted payload has `"water_level_percentage": null`.
  4. Confirm HTTP response is 200.
  5. Confirm DB stores `water_level_percentage = NULL`.
  6. Confirm Admin Portal shows `'Awaiting data'` and Resident Portal shows `'N/A'`.
  7. Confirm NO false low water alert is triggered.
  8. Reconnect `ECHO` wire and confirm normal readings resume.
- [ ] **Q. Wi-Fi Disconnect / Reconnect Resilience**:
  1. Temporarily toggle off Wi-Fi router / mobile hotspot.
  2. Confirm Serial Monitor logs `[WiFi] Lost connection. Reconnecting...` and retries safely without crashing or hanging.
  3. Re-enable Wi-Fi. Confirm ESP32 reconnects automatically and resumes periodic telemetry transmission.
